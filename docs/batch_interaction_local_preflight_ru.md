# Ограниченное задание локальному агенту: подготовка Q2 и одиночного согласия

Цель: собрать фактические условия для следующего испытания, без установки, включения политик и ответа на согласование. Это инвентаризация, не MP-3/Q2 или приёмка согласия человека.

## Исходная точка и точные пути

Запустить агента из выбранной пользователем рабочей копии `dilukhin/opencode_permissions`. Сначала определить абсолютный корень, HEAD/ветку и dirty state; проверить remote URL. Если это другой репозиторий, остановиться. Прочитать AGENTS.md, opencode_permissions_agent_guide_ru.md и существующий `<workspace>/docs/workspace_layout_local.md`.

Не угадывать местоположение другой копии и не искать её по всей машине. В отчёте явно указать выбранные workspace/repository paths; проверяемые ссылки документов должны принадлежать PR Q1, содержащему это задание, либо соответствующему опубликованному коммиту. Если нужного документа нет локально, допустимо прочитать его через подключённый GitHub, но не выполнять pull/checkout и не менять рабочую копию ради инвентаризации.

## Разрешённые действия

1. Read-only: версия ОС и архитектура; текущая учётная запись; пути разрешения opencode и toolchainctl, их версии. На Linux `command -v`, `type -a`, `--version`; на Windows Get-Command, `--version`. Не запускать обычный рабочий сеанс OpenCode.
2. Проверить наличие и владельцев известных файлов конфигурации по правилам текущей версии. Читать только безопасные сведения о permission/plugin слоях; не выводить provider credentials, auth-файлы, environment dump или сырой полный config. При сомнении сообщить путь/наличие без содержимого. Эффективную конфигурацию не считать доказанной по одному файлу.
3. Выяснить по существующим средствам, есть ли уже одноразовая Linux VM/контейнер с отдельными UID, отдельным терминалом владельца и изоляцией от рабочих ключей/relay. Только read-only статус выбранного средства; не создавать VM/контейнер, не запускать daemon и не давать себе root.
4. Зафиксировать, какую платформу и версию можно использовать для одинаковых будущих задач до/после. OpenCode 1.19.0/Q1 не считать разрешённым для P0; 2.0.23 из PR #47 не считать разрешённым для рабочего развёртывания. Проверить exact registry, не подбирать ближайшую версию и не понижать/обновлять OpenCode.
5. Дать агрегированный отчёт. Если создаётся локальный файл, использовать `<workspace>/evidence/batch-preflight/`, только после определения workspace по локальной карте; raw evidence не коммитить.

## Запрещённый объём

Нет install/update, p0 enable/disable, изменения config/policy, создания пользователей, sudo/systemctl, SSH/VPS/cloud mutations, эксплуатации прежнего root-enabled relay, ввода ДА/нажатия согласия агентом, автоматического ответа через HTTP/PTY и изменения репозиториев. Не превращать отказ/недоступность в обход другим транспортом.

## Ожидаемый отчёт

```text
workspace/repository absolute paths:
repository branch/HEAD/dirty state:
OS/architecture/current user:
opencode resolved paths/version:
toolchainctl resolved paths/version:
permission/plugin layers: safe summary or NOT_INSPECTED + reason
exact deployable profile: present/absent/unknown
disposable Linux environment: available/absent/unknown
separate UID and human-owner terminal: available/absent/unknown
credentials/production isolation: confirmed/not_confirmed
suggested next bounded experiment: Q2 observation / synthetic manual console / blocked
files/config/system changes: none
stop reasons:
```

При неожиданном repo/config, недостаточной изоляции, требовании установки/прав или недоступных данных остановить затронутый путь и вернуть evidence. Не выбирать архитектуру вместо Web и не инициировать испытание исполнения.

## Следующая отдельная проверка после инвентаризации

Web задаёт точные пути, версии, испытуемую задачу и команды для выбранной среды. Для Q2 используются одинаковые реальные задачи, та же версия/модель и прямой счёт прерываний до/после; изменения инструкций — через владельца установки. Для консоли — синтетическая операция, подготовленная за защищённой границей, и ручной ввод пользователя approve/reject/no-response. Эти две проверки независимы и не объявляют A1 или сквозное исполнение готовыми.
