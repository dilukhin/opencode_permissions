# Gate B — canonical OpenCode permission artifact contract

Статус: **CONTRACT ACCEPTED / NO DEPLOYABLE ARTIFACT EMITTED**  
Дата: 2026-09-02  
Проект: `dilukhin/opencode_permissions`

## 1. Решение

Gate B фиксирует минимальный стабильный contract между владельцем authorization semantics (`opencode_permissions`) и будущим installer/reconciler (`opencode_setup`).

На этом этапе **не создаются** production:

```text
policy/native/rules.v1.json
dist/opencode/.../permission.jsonc
```

Причина: current exact profile OpenCode `1.18.26` всё ещё `deployable=false` до Windows B-P2 и final Gate B closure.

## 2. Целевая структура после closure

```text
policy/
  native/
    rules.v1.json

dist/
  opencode/
    <artifact-id>/
      permission.jsonc
      manifest.json
```

`rules.v1.json` принадлежит `opencode_permissions` и является canonical ordered semantic source.

Renderer также принадлежит `opencode_permissions`. `opencode_setup` получает уже сгенерированный artifact и не меняет порядок/смысл permission rules.

## 3. Manifest contract

Machine-readable schema зафиксирована в:

```text
tests/artifact_contract/manifest.schema.json
```

Формат:

```text
opencode-permission-artifact/v1
```

Обязательные logical fields:

```yaml
schema: 1
artifact_format: opencode-permission-artifact/v1
artifact_id: sha256:...
status: candidate|deployable
owner: dilukhin/opencode_permissions

target:
  product: opencode
  exact_version: ...
  compatibility_profile_id: ...

policy_source:
  path: policy/native/rules.v1.json
  sha256: ...

renderer:
  id: opencode-v1-permission-renderer
  version: 1

output:
  relative_path: permission.jsonc
  sha256: ...

constraints:
  exact_version_only: true
  requires_deployable_profile: true
  nearest_version_fallback: false
  setup_semantic_rewrite: false
  effective_readback_required: true
  competing_effective_layer_result: CONFLICT
```

## 4. Artifact identity

`artifact_id` не является произвольным release label.

Он вычисляется как domain-separated SHA-256 от canonical JSON identity core:

```text
UTF8("opencode_permissions.artifact.v1\n")
+
canonical JSON of:
  artifact_format
  owner
  target
  policy_source_sha256
  renderer
  output_sha256
```

JSON для этого bounded contract сериализуется детерминированно (`sort_keys`, compact separators, UTF-8).

Изменение target version/profile, source digest, renderer identity/version или output digest меняет artifact identity.

## 5. Required pre-deploy validation

До любой future mutation setup path обязан проверить:

```text
manifest status == deployable
semantic owner == dilukhin/opencode_permissions
installed OpenCode version == target.exact_version
exact compatibility profile version matches installed version
manifest profile_id == selected exact profile_id
profile.deployable == true
policy source digest matches
permission.jsonc digest matches
artifact_id recomputes exactly
nearest-version fallback disabled
setup semantic rewrite disabled
```

Любое несоответствие -> fail closed до mutation.

## 6. Effective layer ownership

Manifest не разрешает `opencode_setup` делать permissive merge собственных authorization rules.

Инварианты:

```text
setup_semantic_rewrite = false
competing_effective_layer_result = CONFLICT
effective_readback_required = true
```

Если обнаружен competing live permission writer/layer, setup сначала должен вернуть conflict/read-only diagnosis. Он не выбирает «более удобный» merge и не удаляет неизвестный user-owned state.

Метод безопасного installation/read-back реализуется Gate F, но обязан сохранить эти semantics.

## 7. Content integrity

Два digest обязательны и имеют разный смысл:

- `policy_source.sha256` связывает artifact с canonical logical source;
- `output.sha256` защищает точные generated bytes `permission.jsonc`.

Validator отдельно отвергает mismatch каждого digest.

## 8. Current profile intentionally cannot deploy

Current exact profile:

```text

overall = SOURCE_REVALIDATED

Windows = SOURCE_REVALIDATED

```

Поэтому test validator обязан вернуть:

для current real profile даже при syntactically valid manifest.

Положительный contract path тестируется только на synthetic copy профиля с `deployable=true`; это не меняет repository profile и не является production evidence.

## 10. Ownership boundary с `opencode_setup`

### `opencode_permissions`

Владеет:

- ordered policy source;
- renderer;
- compatibility profile semantics;
- generated permission artifact;
- manifest/content identity.

### `opencode_setup`

В будущем владеет:

- exact installed-version detection;
- exact artifact selection;
- filesystem/install ownership;
- backup/reconciliation mechanics;
- competing-layer inventory/conflict handling;
- post-apply effective-state verification.

Setup не владеет ALLOW/ASK/DENY semantics.

## 11. Gate conclusion

Canonical artifact/interface contract Gate B считается **закрытым на design/test level**.

Это не означает, что deployable artifact уже существует. Его emission разрешается только после того, как exact compatibility profile удовлетворяет remaining Gate B acceptance и final closure явно разрешит promotion.

После этого contract не требует redesign для Gate F: `opencode_setup` получает exact version/profile/artifact/digest rules и обязан fail closed при drift/conflict.
