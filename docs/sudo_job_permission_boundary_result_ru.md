Испытательный CLI собран без встроенных веб-ресурсов; соответствие установленному официальному бинарному файлу не заявляется.

Шесть испытаний настоящего Permission.Service прошли: ожидание и одноразовое продолжение; reject; configured deny; отмена ожидающего вызова; закрытие host; отдельное разрешение stop. В журнале CI: 6 pass, 0 fail, 26 проверок. Вместо удалённого исполнения использован только локальный массив.

В отдельном опыте настоящий child из Session.shell смог ответить `once` на синтетический pending request другой session в том же проекте. Успех проверен ответом HTTP 204 и исчезновением этого request из pending list. Это произошло в обоих испытанных режимах: default и stdio. В журнале CI: `child_can_reply={"default":true,"stdio":true}`.

Оба сервера получали только случайный синтетический OPENCODE_PASSWORD и очищенную среду. Child не получал пароль в argv; проверяемые источники ограничены его собственной средой и /proc/PID/environ созданного испытательного сервера. Рабочие credentials, другие процессы, SSH, sudo и VPS не использовались.

## Граница вывода

Ответ API и аутентификация сервера в испытанной конфигурации не доказывают, что разрешение дал человек. Прямое потребление native once для допуска sudo-job не принимается в этих режимах и конфигурации.

Это не доказательство обхода configured deny: запрет проверен отдельно и сохранился. Результат не переносится автоматически на service mode, Windows или все варианты конфигурации. Настоящее нажатие в интерфейсе и исполнение через недоверенное расширение остаются отдельными проверками.

Санитизированный JSON сохранён в artifact run 37752192829, id 11537918788. Из этой Web-среды ZIP прочитать не удалось: две свежие ссылки вернули HTTP 403. Поэтому подробная атрибуция успешного ответа конкретному credential-источнику и SHA-256 бинарного файла здесь не переписаны из непрочитанного архива. Основной вывод подтверждён непосредственно проверками и журналом CI.

## Следующее действие

Требуется технически защищённая граница согласия: отдельный доверенный посредник либо доказанная изоляция интерфейса и execution host. Агентский процесс и недоверенное расширение не должны иметь возможность выдавать решение, читать credential согласия или изменять состояние выдачи.

Разрешение связывается с неизменяемой операцией, точными байтами команды, SSH identity, UUID задания/транзакции и действующим execution host; start и stop разрешаются отдельно. Одноразовый допуск потребляется до запуска. Отмена, завершение host, подмена и повтор сохраняют отказ от выполнения. Настоящее согласие человека проверяется дополнительно.

Реестр совместимости не расширен до 2.0.23; PR #47 и agent-safe PR #37 остаются черновиками. ssh_relay#52 остаётся открытой. Транспорт sudo-job повторно реализовывать не требуется.

## Локальные тесты ssh_relay в Web

Прежние 4 ошибки импорта и ошибка packaged doctor связаны с отсутствующим paramiko. Запуск локальной fixture подтвердил другую проблему: PID процесса, возвращаемый системным API, не соответствует PID в смонтированном /proc. Job-runner завершился с exit_code=126 до публикации PID; process identity получила platform=weak/start=null. Это объясняет launcher_failed и неопределённость process-death checks. Runtime-код под эту среду не меняется; полный локальный suite не объявляется успешным. Требуемые испытания выполняются в GitHub CI с согласованными PID и /proc.
