# YC59: защищённый источник запретов владельца

`yc_owner_native_veto.NativeVeto` вычисляет решение из двух канонических
источников `policy/native/rules.v1.json` и `policy/yc/yc_policy.v1.json`.
Ответы permission API, плагины, Shell и весь процесс OpenCode остаются
недоверенными. Их `allow`, `once`, `approved` и переданные строки команд
не входят в этот интерфейс. Новый модуль не выдаёт согласия и не хранит его.

Граница полномочий переносится вместе с существующими каноническими правилами
во внешний защищённый процесс. Источником текущих обязательных запретов для
него служит **активный защищённый выпуск политики владельца**, а не изменяемое
состояние внутри OpenCode. Состояние памяти недоверенного процесса невозможно
считать удостоверенным наблюдением его API. Произвольные дополнительные
проектные или сеансовые правила OpenCode этим модулем не импортируются и не
объявляются проверенными. До активации установщик обязан подтвердить полный
авторитетный набор политики, а при конфликте или неподдержанной конфигурации
отказать. Установленный guard и его политики этот код не меняет.

Конструктор получает точные байты двух источников и их закреплённые SHA-256.
Неверные хеши, повторные ключи JSON, неизвестная семантика, неполная структура
запретов или превышение размеров приводят к отказу. Ревизия решения включает
оба хеша и версию профиля. Нативный корень запуска должен до Python проверить
владельцев, ACL и обычные объекты этих файлов, удерживать их вместе с кодом
проверки весь срок работы и передать проверенные байты. Сам конструктор эту
защиту не доказывает. Замена активной политики требует завершить старый host,
погасить его Ledger и запустить новый с новой ревизией; незаметная горячая
подмена политики недопустима.

`exact_read_argv` — единственный конструктор трёх команд чтения для проверки
и исполнения. В нём нет `list`, мутаций или произвольного argv клиента.
Проверяется логическое написание `yc …` и фактический путь Windows с аргументами;
это консервативные проекции явного запуска без оболочки. Общая реализация
Wildcard/last-match перенесена из проверенного сопоставителя Gate B, который
продолжает использовать её же в корпусе. Это самостоятельное вычисление
канонической семантики `v1_last_match_wins`, а не заявление о версии или текущем
поведении установленного OpenCode.

Любой итоговый native `deny` на одном из трёх чтений прекращает операцию.
Затем применяется общий с существующим классификатором YC жёсткий запрет;
его логика вынесена без изменения правил. Native `allow` по-прежнему требует
настоящего разового согласия через единственный Ledger. При смене ревизии
проверка потребления отклоняет прежнее согласие до запуска; возврат к прежней
политике не восстанавливает его.

Проверки покрывают настоящие канонические источники, адресный запрет каждой
проекции, приоритет запретов YC, неверные источники и сжигание выданного once
при смене политики. Сборка компонента включает модуль и точные источники,
сохраняя `execution_enabled=false` и все требования до активации. Подключение
этого источника в нативный корень запуска, доверенный контекст/запуск и
управляемая активация ещё обязательны; этот шаг сам по себе не закрывает #59.
