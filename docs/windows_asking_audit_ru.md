# Windows: повторный подсчёт форм `asking` для OpenCode 1.18.32

Локальный отчёт от 2026-10-04 отнёс 3208 из 3208 `permission=bash` к `unknown`, потому что проверка поля `patterns` завершилась до классификации. В официальном коде `Permission.ask` журналирует `patterns` как массив; текстовый журнал может представлять его как JSON-строку, содержащую JSON-массив. Счётчик `tools/windows_asking_audit.py` разбирает обе формы и не сохраняет исходные строки.

На той же Windows-машине, где находится исходный журнал, из checkout проекта:

```powershell
py -3 tools/windows_asking_audit.py
```

Скрипт читает `%USERPROFILE%\.local\share\opencode\log\opencode.log` за один проход и пишет в стандартный вывод только агрегаты: общее число `asking` и `bash`, частоты восьми точных фиксированных форм, остальные одиночные и множественные шаблоны, ошибки разбора, долю `unknown` и контроль суммы. Дополнительно он считает только заранее заданные семейства по началу каждого шаблона: отдельно для одиночных запросов и для множественных запросов (семейство встречается хотя бы раз / все шаблоны того же семейства), а также число шаблонов в массиве. Передать итоговый JSON в задачу #39 без исходного журнала. Если `py` недоступен, можно запустить тот же файл установленным Python 3 (`python tools/windows_asking_audit.py`). Никаких настроек OpenCode скрипт не меняет.

Имена фиксированных форм и семейств в выходном JSON заранее заданы, а не извлечены из команд. Любой шаблон вне восьми точных форм остаётся в `unknown`, даже если он получил диагностическое семейство «Git» или «чтение». Семейство определяется по началу текста, может включать составную команду и **не доказывает безопасность**. Массив с несколькими шаблонами не разбивается на независимые команды при выборе кандидата на разрешение. Счётчик не является интерпретатором PowerShell и не выдаёт разрешений. `asking` в журнале не равно гарантированному числу показанных человеку окон. Данные могут охватывать несколько проектов и агентов, поэтому частота в журнале не доказывает сокращение запросов в конкретном проекте.

Перед включением нового правила нужны проверка действующих глобальных, агентских и подключаемых слоёв на пользовательской машине и отдельный цикл до/после. Windows P0 пока не поддерживается; этот аудит сам по себе его не включает.
