## Отклонение, которое нельзя превратить в PASS

Исполнитель сообщил запись в постоянную память агента вне разрешённого каталога.
Ограничение места записи не соблюдено. Объяснение «обязательное правило памяти»
не доказывает неизбежность записи или приоритет этого правила над заданием:
источник правила и содержимое изменения здесь не исследовались.

Поэтому полный read-only gate не закрыт. При этом отклонение не отменяет
совпавшие хеши четырёх файлов и полученную версию. Нельзя расширять этот вывод
до «вся система осталась неизменной». Значение persistent_environment_changes=1
в отчёте описывает запись файла; из него не следует изменение PATH или реестра.

Не откатывать, не удалять и не запрашивать полный файл памяти. Для следующего
ограниченного задания конфликт инструкций должен быть выявлен до записи:
если исполнитель не может соблюсти границу, он останавливает затронутую работу
и сообщает об ограничении. Автоматическую запись компонента установки нельзя
исправлять ручным изменением настроек в рамках read-only проверки.
Это локальное отклонение исполнения задания; новый инцидент GitHub Connector
из него не следует. Повтор всего YC59-PREFLIGHT-01 не требуется.

## Exact-version исследование

Текущий реестр совместимости не содержит 1.19.5 и не допускает ближайшую версию
вместо точной. Прежние проверки 1.18.32/1.19.0/2.0.23 не принимаются за приёмку
установленного 1.19.5. Работающий переходный YC guard при этом не заменяется
и не объявляется сломанным из-за отсутствия общего профиля OpenCode 1.19.5.

Официальный tag v1.19.5 указывает на
`810c0eba1a7348036f8bdf61e6632d0c36c6876c`. По исходникам этой ревизии:

- permission service создаёт pending-запрос и после `once` завершает только
  соответствующее ожидание; `always` отдельно добавляет правила;
- HTTP reply принимает requestID/reply/message, но не свидетельство личности
  физического человека;
- серверная аутентификация задаётся отдельными настройками; владение доступом
  к API нельзя автоматически приравнивать к действию владельца в UI;
- exposed tool/permission key остаётся `bash`, несмотря на перенос реализации
  оболочки и HTTP в новые модули.

Источники на точном commit:

- [HTTP handler](https://github.com/anomalyco/opencode/blob/810c0eba1a7348036f8bdf61e6632d0c36c6876c/packages/opencode/src/server/routes/instance/httpapi/handlers/permission.ts).

## Следующий опыт без повторного задания локальному агенту

Выбран узкий опыт на Windows CI: официальный бинарник 1.19.5, архив закреплён
SHA-256/размером из [официального выпуска](https://github.com/anomalyco/opencode/releases/tag/v1.19.5),
временные home/project и локальная имитация модели. Используются четыре базовых
сценария существующего Windows-стенда: native allow, deny, ask→once и ask→reject.
Фрагмент диагностической policy 1.18.32 не применяется к 1.19.5.

Реальная команда только выводит синтетическую строку. Согласие в опыте выдаёт
автоматический HTTP-контроллер, поэтому даже успешный результат не доказывает
действие человека. Вывод всегда явно содержит human_consent_proven=false,
yc_authorization_binding_proven=false, installed_dima_hp_binary_proven=false
и deployment_authorized=false. Политика YC, реестр совместимости и установленная
конфигурация не меняются; облачных вызовов нет.

Критерий опыта: четыре подтверждённых исхода на точном официальном бинарнике.
Отказ/несовместимость не обходятся другой версией или широким allow. Результат
публикуется после фактического CI; наличие стенда не означает пройденный опыт.
Он проверяет механику API, а не подлинность владельца, повторное потребление,
отмену сессии, полный threat model или возможность восстановления снимка.

После опыта источник доверенного согласия и его связь с actual operation остаются
отдельным условием подключения. Автоматический `once`, вопрос модели, собственный
JSON-флаг и подтверждение изнутри выполняющего агента не открывают YC dispatcher.
