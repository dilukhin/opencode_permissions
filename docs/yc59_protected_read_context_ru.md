# YC59: контекст защищённого процесса владельца

`WindowsReadContext` используется только после нативного запуска из toolchain
#123. До загрузки Python тот проверяет и удерживает интерпретатор, весь компонент,
конфигурацию и предков, закрывает процесс/токен и Default DACL будущих объектов,
назначает группу процессов Windows. Сам Python этого начала доверия не доказывает.
Модуль не имеет отдельного интерфейса командной строки и не получает источники,
секреты или функцию исполнения из запросов OpenCode.

Закреплён официальный YC 1.39.0 windows/amd64, 196325832 байта, SHA-256
`7dc58200b8ecba6913ec3f9961d0fda21ee3b67fa6972dad0cffdde5198acb94`.
Источник — официальный версионный URL Yandex Cloud, наблюдение Windows CI
toolchain run 42468083025. Там проверены версия, справка и разбор полного argv
каждого из трёх чтений с `--help`, без credentials/API. Это не проверка реальных
облачных ответов и не установленная приёмка.

Контекст повторно открывает бинарный файл и политики как обычные объекты ядра
без совместной записи/удаления, проверяет SHA/размер/фактический путь, тип,
число ссылок и сохраняет идентификатор тома/файла. Проверка `yc version` идёт
с очищенной средой без credentials; вывод должен совпасть с закреплённым.
До каждого запуска повторно сверяются удерживаемые объекты и SID/SessionId
текущего процесса. ACL уже проверены нативным родителем, их проверка изменяемым
Python не используется в качестве начального доказательства.

Доверенная точка входа — `approval_owner/entry.py`. Она допускает только локальную
консоль отдельного владельца и конфигурацию нативного корня с точным manifest SHA.
Человек вводит IAM-токен скрыто, затем точные ID облака/каталога/ВМ/диска/снимка.
Время наблюдения фиксируется после выбора, не обновляется при запросах агента.
По истечении 60 секунд host закрывается; старые согласия не переносятся дальше.
Идентификаторы сеанса/вызова/хоста/credential context создаются внутри владельца.

Среда YC строится заново: системный каталог Windows, системный PATH, закрытые
временный/домашний/конфигурационные каталоги и введённый `YC_IAM_TOKEN`. Чужие
proxy/endpoint/profile/Python/plugin-параметры не наследуются. Secret не входит
в идентификатор среды, операцию, вывод или журнал; контекст credentials обозначен
случайным UUID. При закрытии словарь среды очищается; гарантия стирания всех
копий Python-строки из памяти не заявляется. Память процесса защищена ОС.

Starter принимает только один из трёх точных argv текущего `ReadProfile` и
совпавшее полное описание исполнения. Popen использует явные executable/cwd/env,
DEVNULL stdin, бинарные stdout/stderr, без Shell и наследования посторонних
дескрипторов. Default DACL закрыт **до** Popen: защиты после запуска недостаточно.
Согласие по-прежнему расходует единственный Ledger до вызова starter. Ограничения
общих 30 секунд, выдачи и отсутствия повторов сохраняются.

`describe` возвращает только неподтверждённое описание после OS admission,
без создания разрешения. Уведомление локальной консоли содержит реальный
request ID/SHA из Ledger. Код отображения и проверки человеческого ответа
переиспользуется испытательным стендом; публичного approve CLI нет. Подтверждение
может сделать только владелец с другим SID и другим ненулевым SessionId.

После трёх завершённых чтений владелец печатает в своей консоли отдельную
квитанцию с безопасной проекцией, точными request ID/SHA, component ID и SHA-256
результата. Она формируется из фактического ответа владельца до отправки по
каналу и остаётся доступной при потере ответа агентом. Очередь этих результатов
ограничена и не хранит согласий; повторное consume не создаёт новой квитанции.
Агент и владелец могут сопоставить один и тот же хеш без публикации raw YC или
credentials. Совпадение не доказывает возможность восстановления снимка.

Компонент всё ещё `library_only`, `execution_enabled=false`; entry отказывается
его запускать. До разрешённой активации обязательны связанный нативный выпуск,
проверка Windows-пути этого контекста и управляемая подготовка с журналом.
Общий Python, установленный guard, старые G3/G4 и облачные ресурсы не меняются.
